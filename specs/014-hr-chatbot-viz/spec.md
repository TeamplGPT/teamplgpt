# Feature Specification: HR 챗봇 시각화(조직도·근무현황·급여추세)

**Feature Branch**: `feature/skill-modify-hrchat-merge`

**Created**: 2026-09-16

**Status**: Draft

**Input**: User description: "HR 챗봇 위젯(okrservice)에 조직도(Mermaid)·근무현황요약(Chart.js)·급여추세(Chart.js) 시각화 추가. 사용자가 명시적으로 '그래프/차트/도표로 보여줘'라고 요청했을 때만, teamplgpt가 기존 hr-personnel(org_members)/hr-attendance(work_status)/hr-salary(salary_statement) tool 결과를 고정 JSON 스키마(```viz 코드블록: type=orgchart/workstatus/salarytrend)로 출력하고, okrservice의 ChatbotView.tsx 렌더러가 이를 감지해 Mermaid/Chart.js로 렌더링한다. 조직도는 회사 전체가 아닌 '내 팀 구성원 1단 트리' 범위로 한정. teamplgpt 신규 백엔드 조회 로직 추가 없음(기존 tool 결과 재사용만). 작업 브랜치는 두 저장소 모두 feature/skill-modify-hrchat-merge."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 근무현황을 그래프로 확인 (Priority: P1)

임직원이 okrservice HR 챗봇 위젯에서 "이번 달 근무현황 그래프로 보여줘"라고 물으면, 텍스트 표 대신(또는 함께) 정상/지각/조퇴/결근 등 항목별 건수를 막대 그래프로 즉시 확인할 수 있다.

**Why this priority**: 세 가지 시각화 중 데이터 구조가 가장 단순(라벨-값 쌍)하고 이미 서버에 집계 로직(근무현황 요약)이 존재해 검증 리스크가 가장 낮다. 첫 구현 대상으로 나머지 두 가지의 렌더링 파이프라인(코드블록 감지→차트 렌더)을 검증하는 기준선이 된다.

**Independent Test**: 위젯에서 "근무현황 그래프로 보여줘"만 입력해 막대 그래프가 표시되는지 확인 — 조직도·급여추세 기능 없이도 단독으로 가치를 제공한다.

**Acceptance Scenarios**:

1. **Given** 임직원이 위젯에서 챗봇과 대화 중, **When** "이번 달 근무현황 그래프로 보여줘"라고 입력, **Then** 근무현황 항목별(정상/지각/조퇴/결근 등) 건수가 막대 그래프로 렌더링된다.
2. **Given** 동일 조건, **When** "이번 달 근무현황 알려줘"처럼 그래프를 명시하지 않고 질문, **Then** 기존과 동일하게 텍스트 요약/표로만 응답하고 그래프는 표시되지 않는다.

---

### User Story 2 - 급여추세를 그래프로 확인 (Priority: P2)

임직원이 "최근 급여 추세를 그래프로 보여줘"라고 물으면, 월별 실지급액 등 급여 항목의 변화를 선 그래프로 확인할 수 있다.

**Why this priority**: 이미 연 단위 월별 급여 데이터를 한 번에 조회하는 기능이 존재해 추가 조회 없이 시계열 그래프를 구성할 수 있지만, 항목(실지급액/공제 등) 선택 로직이 근무현황보다 한 단계 더 있어 P1 다음 순위로 둔다.

**Independent Test**: 위젯에서 "급여추세 그래프로 보여줘"만 입력해 월별 선 그래프가 표시되는지 확인 — 다른 두 시각화 없이도 단독으로 가치를 제공한다.

**Acceptance Scenarios**:

1. **Given** 임직원이 위젯에서 챗봇과 대화 중, **When** "최근 급여 추세 그래프로 보여줘"라고 입력, **Then** 월별 급여 항목(실지급액 등)의 변화가 선 그래프로 렌더링된다.
2. **Given** 조회 기간에 해당하는 급여 데이터가 1개월치뿐인 경우, **When** 그래프를 요청, **Then** 시스템은 오류 없이 단일 지점 그래프(또는 자연스러운 축소 표현)를 표시한다.

---

### User Story 3 - 소속 팀 구성원을 조직도로 확인 (Priority: P3)

임직원이 "우리 팀 조직도 보여줘"라고 물으면, 본인이 속한 팀의 팀장·구성원 관계를 트리 형태의 다이어그램으로 확인할 수 있다.

**Why this priority**: 가치는 있으나 회사 전체 조직도가 아닌 "내 팀 1단계" 범위로 한정되어 체감 효용이 상대적으로 낮고, 다이어그램 문법 생성이라는 별도 변환 경로(JSON→Mermaid)가 필요해 검증 항목이 가장 많다.

**Independent Test**: 위젯에서 "우리 팀 조직도 보여줘"만 입력해 트리 다이어그램이 표시되는지 확인 — 다른 두 시각화 없이도 단독으로 가치를 제공한다.

> **구현 중 발견 및 해결(E2E-First로 확인)**: "조직도"라는 단어만으로는 기존 hr-personnel 라우팅이 `org_tree`(부서 구성 코드 트리, 사람 정보 없음)로 응답해 이 스토리가 필요로 하는 `org_members`(팀 구성원 명단)와 다른 데이터를 반환했다(plugin.json의 `examples` few-shot이 "조직도 보여줘"→`org_tree`로 고정돼 있었던 것이 근본 원인). "팀원 목록을 조직도로"처럼 우회 표현을 요구하는 것은 실사용자 어법과 맞지 않는다는 피드백에 따라, hr-personnel의 `query_type` 판별 문구와 `examples`를 수정해 "조직도"만으로도 `org_members`로 정확히 라우팅되도록 고쳤다(§7 적용 현황·`evals/hr-routing/dataset.jsonl` per-org-01 갱신 포함). `hrSkillGuard.js`의 `[HR_VIZ_OUTPUT]`도 "조직도" 자체를 시각화 트리거로 인정하도록 확장했다(그래프/차트/도표 같은 별도 키워드 없이도 동작).

**Acceptance Scenarios**:

1. **Given** 임직원이 위젯에서 챗봇과 대화 중, **When** "우리 팀 조직도 보여줘"라고 입력, **Then** 본인 소속 팀 명칭을 루트로, 팀 구성원을 하위 노드로 하는 1단계 트리 다이어그램이 렌더링된다.
2. **Given** 임직원이 속한 팀 구성원이 1명(본인만)인 경우, **When** 조직도를 요청, **Then** 시스템은 오류 없이 루트 노드와 단일 하위 노드만 있는 다이어그램을 표시한다.

---

### Edge Cases

- 그래프 요청 문장이 근무현황/급여/조직도 중 어느 도메인인지 모호한 경우("이거 그래프로 보여줘"만 입력) → 직전 조회 결과가 있으면 그 도메인 기준으로 처리하고, 없으면 기존처럼(모호성 안내 또는 재질문 없이 즉시 tool 호출 우선 원칙에 따름) 가장 최근 언급된 도메인으로 처리한다.
- 조회 결과가 0건(예: 이번 달 근무 이력 없음, 급여 데이터 없음)인 경우 → 그래프 대신 "표시할 데이터가 없습니다" 안내 텍스트만 응답한다.
- 챗봇이 시각화 데이터를 정상 형식으로 생성하지 못한 경우(형식 깨짐) → 사용자에게는 원본 텍스트/표 응답만 보이고 그래프 영역은 조용히 생략된다(오류 메시지나 깨진 화면 노출 없음).
- 동일 대화에서 같은 그래프를 반복 요청하는 경우 → 매번 최신 조회 결과 기준으로 다시 렌더링한다(캐시된 이전 그래프 재사용 안 함).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자가 그래프/차트/도표 등 시각화를 명시적으로 요청한 경우에만 시각화를 제공해야 한다. 명시적 요청이 없으면 기존과 동일하게 텍스트/표로만 응답한다.
- **FR-002**: 시스템은 근무현황 데이터를 항목별 건수 막대 그래프로 시각화할 수 있어야 한다.
- **FR-003**: 시스템은 급여 데이터를 기간(월)별 추이 선 그래프로 시각화할 수 있어야 한다.
- **FR-004**: 시스템은 사용자 소속 팀의 조직도를 팀장/구성원 관계를 나타내는 트리 다이어그램으로 시각화할 수 있어야 한다. 범위는 사용자가 속한 팀 1단계로 한정하며, 회사 전체 다단계 조직도는 포함하지 않는다.
- **FR-005**: 시각화에 사용되는 값은 반드시 실제 조회된 데이터와 일치해야 하며, 임의로 생성되거나 왜곡된 값이 표시되어서는 안 된다.
- **FR-006**: 조회된 데이터가 없거나 시각화를 구성할 수 없는 경우, 시스템은 오류 화면이나 깨진 렌더링 없이 안내 텍스트 또는 원본 텍스트 응답으로 대체해야 한다.
- **FR-007**: 시각화 기능은 신규 데이터 조회 경로를 추가하지 않고, 기존에 이미 제공되던 조회 결과(근무현황 요약, 급여 내역, 팀 구성원 목록)만을 재사용해야 한다.
- **FR-008**: 시각화는 사용자가 챗봇을 사용하는 화면(임베드형 위젯) 내에서 표시되어야 한다.

### Key Entities

- **근무현황 요약**: 특정 기간 동안의 근태 상태(정상/지각/조퇴/결근 등)별 건수. 이미 존재하는 근무현황 조회 결과를 그대로 사용.
- **급여 항목 추이**: 월별 급여 지급 내역(실지급액 등) 목록. 이미 존재하는 급여 조회 결과를 그대로 사용.
- **팀 구성원 트리**: 사용자가 속한 팀 명칭과 그 팀에 속한 구성원(이름·직위) 목록. 이미 존재하는 팀 구성원 조회 결과를 그대로 사용.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 "근무현황/급여추세/조직도를 그래프(차트/도표)로 보여줘"라고 요청하면, 추가 안내나 재질문 없이 한 번의 응답 안에서 해당 시각화가 표시된다.
- **SC-002**: 시각화를 요청하지 않은 기존 질문들의 응답 형식(텍스트/표)에는 변화가 없다(회귀 없음).
- **SC-003**: 시각화 대상 데이터가 없거나 형식이 깨진 경우에도 챗봇 화면이 깨지거나 오류가 노출되는 사례가 0건이어야 한다.
- **SC-004**: 세 가지 시각화 각각에 대해 실제 위젯 환경에서 요청 시 그래프/다이어그램이 표시되는 것을 최소 1회 이상 실제 조회로 검증한다(데모 가능 상태).

## Assumptions

- 시각화 대상 데이터는 이미 각 HR 조회 기능이 반환하는 결과 범위 내로 한정한다(신규 필드·신규 조회 없음).
- 조직도는 "사용자가 속한 팀"의 구성원 1단계 범위로 한정하며, 팀장-구성원 간 관계는 별도 계층 정보 없이 팀 소속 여부만으로 표현한다.
- 시각화는 사용자가 명시적으로 시각화를 요청한 경우에만 노출되며, 자동으로 항상 표시되지는 않는다.
- 본 기능은 okrservice HR 챗봇 위젯(임베드형)에서만 제공되며, 다른 채팅 화면/모드에서의 시각화 노출 여부는 본 스펙 범위에 포함하지 않는다.
- 작업은 teamplgpt·okrservice 두 저장소의 `feature/skill-modify-hrchat-merge` 브랜치에서 진행한다.
