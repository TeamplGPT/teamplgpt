# Contract: 공통 시스템 지시 변경 (`server/utils/hrSkillGuard.js` · `hrSkillCommonLines()`)

채팅/query·react·embed(`hrSkillChatGuard`)와 @agent(`hrSkillPeriodGuard`)가 이 모듈을 공유한다. 4번 규칙만 바꾼다. 다른 규칙과 각 skill `plugin.json` description은 수정하지 않는다(spec D4).

## 4번 규칙 — 변경 전

```text
4. year_month 전달 규칙: 연도 명시 시 'YYYYMM'(예: '202503')/'YYYY-MM'/'YYYY년 M월' 중 하나, 연도 미명시 시 월 표현('3', '2월', '지난달')을 그대로 전달(현재 연도 자동 적용). 월 단위 조회이므로 일(day) 정보는 무시하고 월만 전달하세요.
```

## 4번 규칙 — 변경 후

```text
4. year_month 전달 규칙: 연도 명시 시 'YYYYMM'(예: '202503')/'YYYY-MM'/'YYYY년 M월' 중 하나, 연도 미명시 시 월 표현('3', '2월', '지난달')을 그대로 전달(현재 연도 자동 적용). 일(day) 정보는 무시하고 월만 전달하세요. 사용자가 월 없이 연도만 말하면('올해', '이번년도', '작년', '2026년') 그 표현을 year_month(연말정산은 cal_yy)에 그대로 전달하세요 — 생략하거나 특정 월로 바꾸지 마세요. 서버가 그해 기준으로 조회합니다. 도구 결과에 '조회 기간'이 있으면 그 기간보다 넓은 범위를 조회했다고 말하지 마세요.
```

## 4번 규칙 — 1차 확정본 (T020 검증 중 보정 — 아래 최종본으로 대체됨)

```text
4. year_month 전달 규칙: 사용자가 월 없이 연도만 말하면('올해', '이번년도', '작년', '2026년') 그 표현을 year_month(연말정산은 cal_yy)에 그대로 전달하세요 — 생략하거나 특정 월(예: '202601')로 바꾸지 마세요. 서버가 그해 기준으로 조회합니다. 연도와 월을 함께 말하면 'YYYYMM'(예: '202503')/'YYYY-MM'/'YYYY년 M월' 중 하나, 연도 미명시 시 월 표현('3', '2월', '지난달')을 그대로 전달(현재 연도 자동 적용). 일(day) 정보는 무시하고 월만 전달하세요. 도구 결과에 '조회 기간'이 있으면 그 기간보다 넓은 범위를 조회했다고 말하지 마세요.
```

## 4번 규칙 — 최종본 (E2E EC-FILTER-03 회귀 수정, 2026-10-15)

```text
4. year_month 전달 규칙(호출할 skill을 이미 정한 뒤 인자를 채우는 방법입니다 — 발화에 기간이 있다는 이유만으로 tool을 호출하지 마세요): 연도와 월을 함께 말하면 'YYYYMM'(예: '202503')/'YYYY-MM'/'YYYY년 M월' 중 하나, 연도 미명시 시 월 표현('3', '2월', '지난달')을 그대로 전달(현재 연도 자동 적용). 일(day) 정보는 무시하고 월만 전달하세요. 사용자가 월 없이 연도만 말하면('올해', '이번년도', '작년', '2026년') 그 표현을 year_month(연말정산은 cal_yy)에 그대로 전달하세요 — 생략하거나 특정 월(예: '202601')로 바꾸지 마세요. 서버가 그해 기준으로 조회합니다. 도구 결과에 '조회 기간'이 있으면 그 기간보다 넓은 범위를 조회했다고 말하지 마세요.
```

1차 확정본은 E2E embed 스위트의 EC-FILTER-03(근태만 허용한 위젯에 "6월 급여명세서 보여줘" → tool 호출 없음 기대)에서 회귀를 냈다. 기간 전달을 강하게 지시하는 문장이 "기간이 있는 HR 질문이면 남은 tool이라도 호출"하는 쪽으로 모델을 기울였다(실패 시 근태 timesheet를 6월로 호출). 전체 tool로 도는 라우팅 평가에는 이 조건(허용 tool 일부)이 없어 잡히지 않았다.

| 4번 규칙 문구 | EC-FILTER-03 (16회) | 연도 케이스 (--grep year 14건) |
|---|---|---|
| HEAD | 10/16 (누적 16/24) — 실패는 연차 잔여 호출(기존) | 1/8 (당시 8건) |
| 1차 확정본 (연도 규칙 먼저) | 1/16 (누적 4/25) — 실패에 timesheet 6월 호출 다수 | 14/14 |
| B: 1차 확정본 + 범위 단서 | 8/16 | 14/14 ×2 |
| C: 월 규칙 먼저 + 연도 규칙 (단서 없음) | 2/16 | 14·13·13 |
| **최종(D): 범위 단서 + 월 규칙 먼저 + 연도 규칙 + 반례** | **12/16** | **14/14 ×3** |

범위 단서 = "(호출할 skill을 이미 정한 뒤 인자를 채우는 방법입니다 — 발화에 기간이 있다는 이유만으로 tool을 호출하지 마세요)". 연도 문장이 있으면 단서 없이는 호출 쏠림이 생기고(C), 단서가 그것을 HEAD 수준 이상으로 되돌린다(D).

## 변경 요지

| 항목 | 이유 |
|---|---|
| "월 단위 조회이므로" 삭제 | 연도 단위 조회가 생겨 사실과 달라진다 |
| 연도만 말하면 그대로 전달 | 라우팅 확인에서 9회 중 2회는 생략, 7회는 "2026"으로 변환해 넘겼다. 생략을 막고, 서버가 해석할 원문 표현을 받는다 |
| '조회 기간'보다 넓게 말하지 말 것 | FR-013. 실사례에서 1월만 조회하고 "2026년 전체"라고 확언했다 |
