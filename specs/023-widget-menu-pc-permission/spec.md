# Feature Specification: 위젯 HR 메뉴 권한에 5240 PC 메뉴 권한 반영

**Feature Branch**: `feature/skill-modify-hrchat-merge` (스펙 디렉토리 `specs/023-widget-menu-pc-permission`)

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "위젯 챗봇 HR 메뉴 바로가기 버튼의 권한 판단을 5240 모바일 메뉴 권한뿐 아니라 PC 메뉴 권한까지 보도록 확장한다(둘 중 하나라도 있으면 보이고 열림)."

**Convention**: HR agent-skill 7종의 `plugin.json` description을 바꾸지 않는다 → `docs/conventions/hr-skill-description-pattern.md` 적용 대상 아님(T-A/T-B 해당 없음).

**관련 저장소**: okrservice(`$OKRSERVICE`, 위젯 챗봇 화면 `widgets/client/messenger/components/chatbot/`·위젯 브리지 `widgets/client/messenger/widget/hrBridge.ts`)만 변경한다. TeamplGPT(이 저장소)는 스펙 문서만 둔다. kiwibox(5240)는 읽기 전용이라 수정하지 않는다.

## 배경

위젯 챗봇은 답변 아래, 입력 중 추천, 근태 알림(RPA) 메시지, 메뉴 목록 화면에 5240 메뉴 바로가기 버튼(34개)을 보여 준다. 버튼을 누르면 5240 **모바일** 화면을 위젯 안에서 연다.

현재 상태(2026-11-17 확인):

- okrservice 기능 브랜치(`feature/skill-modify-hrchat-merge`, 커밋 62cc61e63c·bb93402bcd)에는 직원의 5240 **모바일** 메뉴 목록(`/getMobileMenuList.do`)에 있는 화면만 버튼을 보이는 필터가 있다. 운영 위젯에는 아직 배포되지 않아 지금은 모든 버튼이 보인다.
- 5240은 PC 메뉴와 모바일 메뉴 권한을 **따로** 관리한다. 메뉴 트리에서 모바일 메뉴는 "모바일" 아래에 별도 프로그램(MOS-xxxx)으로 있고, PC 메뉴는 다른 프로그램(TAA-·EAP-·BTR- 등)이다. 둘을 잇는 정보는 5240에 없다.
- 테스트 계정(5240corp, 회사 오이사공)은 PC에 휴가신청(직원)·경조휴가신청(직원)·월별근무계획조회 권한이 있지만 모바일 메뉴 목록에는 휴가신청·경조휴가신청·근무일정조회가 없다. 그래서 필터를 배포하면 **PC에서는 휴가를 신청할 수 있는 직원이 위젯에서는 휴가신청 버튼을 못 본다.**
- PC 권한만 있는 계정으로 모바일 휴가신청 화면(`/MobileLeaveAppl.do`)을 직접 열면 정상으로 뜬다(사용자 확인 2026-11-17). 5240은 화면·데이터 호출 단계에서 메뉴 권한을 검사하지 않는다(`specs/kiwibox-endpoint-test-guide.md` §1.1). 즉 위젯 메뉴 권한은 **보안 경계가 아니라 화면 정리 용도**다.
- PC 메뉴 권한 목록은 5240 `/getSubLowMenuList.do`로 받을 수 있다. 직원용(`menuKind=menu01`)과 업무 담당자용(`menuKind=menu02`)을 따로 조회하고, 세션 값만으로 직원의 권한 그룹을 판단하며, 행마다 프로그램 코드(PROG_CD)·주소(PROG_FILE)·신청 종류(APPL_CD)를 준다(kiwibox `Main_SQL.xml` `getLowMenuList`, PC용 메뉴만: `PC_MOB_TYPE IS NULL OR 'P'`).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - PC 권한만 있는 직원도 위젯에서 해당 메뉴를 연다 (Priority: P1)

오이사공 직원이 위젯에서 "반차 신청은 어떻게 해요?"라고 묻는다. 이 직원은 5240 PC에 휴가신청(직원) 권한이 있지만 모바일 메뉴에는 휴가신청이 없다. 답변 아래 바로가기에 **휴가신청** 버튼이 보이고, 누르면 모바일 휴가신청 화면이 위젯 안에서 열린다.

**Why this priority**: 기능의 존재 이유. 권한 있는 직원이 위젯에서 막히는 문제를 없앤다.

**Independent Test**: PC에만 휴가신청 권한이 있는 계정으로 위젯을 열고 휴가 관련 질문을 한다.

**Acceptance Scenarios**:

1. **Given** PC에 휴가신청(직원) 권한이 있고 모바일 휴가신청 권한이 없는 직원, **When** 위젯에서 휴가 관련 질문, **Then** 답변 아래 휴가신청 버튼이 보이고 누르면 모바일 휴가신청 화면이 열린다.
2. **Given** PC에 월별근무계획조회 권한만 있는 직원, **When** "출퇴근 변경 어떻게 해요?"처럼 근무일정조회 버튼이 붙는 질문, **Then** 근무일정조회 버튼이 보인다.
3. **Given** PC에 경조휴가신청(직원) 권한만 있는 직원, **When** 경조휴가 질문, **Then** 경조휴가신청 버튼이 보인다.

### User Story 2 - 어느 쪽에도 권한이 없는 메뉴는 계속 숨긴다 (Priority: P1, 필수 — D10)

PC에도 모바일에도 급여명세서 권한이 없는 직원이 "이번 달 급여명세서 보여줘"라고 물으면 급여명세서 버튼이 보이지 않는다.

**Why this priority**: 합집합으로 바꿔도 기존 필터의 목적(권한 없는 메뉴 정리)은 지켜야 한다.

**Independent Test**: 특정 메뉴가 PC·모바일 모두에 없는 계정으로 그 메뉴가 붙는 질문을 한다.

**Acceptance Scenarios**:

1. **Given** PC·모바일 모두 급여명세서 권한이 없는 직원, **When** 급여명세서 질문, **Then** 급여명세서 버튼이 보이지 않고 주소로 직접 열려고 해도 열리지 않는다.
2. **Given** 대응표에서 "짝 없음"인 버튼(예: 휴가캘린더)과 모바일 권한이 없는 직원, **When** 그 버튼이 붙는 질문, **Then** PC 권한과 무관하게 숨긴다.
3. **Given** PC에 관리자용 휴가 관리 화면 권한만 있고 직원용 휴가신청 권한은 없는 직원, **When** 휴가 질문, **Then** 휴가신청 버튼이 보이지 않는다(대응표는 직원용 프로그램만 짝지음).

### User Story 3 - 결재 양식 버튼은 신청 종류까지 맞아야 열린다 (Priority: P2)

직원이 PC에 고충신고서(신청 종류 5470) 권한만 있으면 고충신고서 버튼은 보이지만, 같은 화면을 쓰는 근무복신청서(5200-303) 버튼은 보이지 않는다.

**Why this priority**: 한 화면을 여러 신청서가 같이 쓰는 경우의 기존 보호(신청 종류 구분)를 PC 기준에서도 유지한다.

**Independent Test**: PC에 특정 신청 종류 결재 양식 권한만 있는 계정으로 결재 양식 버튼 노출을 확인한다.

**Acceptance Scenarios**:

1. **Given** PC에 신청 종류 5470 권한만 있는 직원, **When** 고충신고서·근무복신청서 버튼이 붙는 질문, **Then** 고충신고서만 보인다.
2. **Given** PC 권한으로 보인 사직서(직원) 버튼, **When** 누름, **Then** 기존과 같은 방식(5240 메뉴 정보로 만든 주소)으로 열린다. 모바일 메뉴 정보가 없으면 PC 메뉴 행의 정보로 주소를 만든다.

---

### Edge Cases

- PC 메뉴 조회만 실패(세션 만료·네트워크 오류·로그인 화면 응답): 모바일 권한만으로 판단한다(D6).
- 모바일 메뉴 조회만 실패: PC 권한만으로 판단한다.
- 둘 다 실패하거나 아직 받는 중: 출퇴근 체크·비밀번호 변경만 보인다(현행).
- 직원용(menu01)은 성공하고 담당자용(menu02)만 실패: 받은 쪽만으로 판단한다.
- PC 메뉴 목록이 수백 행으로 커도 챗봇 첫 화면 표시를 막지 않는다(권한 확인 전에는 항상 허용 화면만 보이는 현행 동작 유지).
- PC 메뉴 행에 사용 중지된 메뉴가 섞여 있어도 5240 조회가 이미 사용 메뉴만 돌려주므로 그대로 쓴다.
- 대응표에 같은 PC 코드가 두 버튼에 걸리는 경우(예: 휴가신청·경조휴가신청이 모두 EAP 결재 화면): 코드 단위로 판단하므로 서로 영향을 주지 않는다.
- 회사 전용 PC 신청서(코드 끝 `-300` 등)만 쓰는 회사: 1차 대응표에 없으므로 모바일 기준으로 판단된다(현행보다 나빠지지 않음).

## Requirements *(mandatory)*

### Functional Requirements

**권한 수집**

- **FR-001**: 챗봇 화면을 열 때 기존 모바일 메뉴 권한과 함께 직원의 5240 PC 메뉴 권한(직원용·담당자용)을 받아야 한다.
- **FR-002**: PC 메뉴 권한 조회는 세션 본인의 메뉴만 돌려주는 조회여야 하며, 다른 직원을 지정하는 값을 보내지 않아야 한다.
- **FR-003**: 위젯 브리지는 PC 메뉴 권한 조회 경로 하나와 그 조회의 메뉴 종류 값 두 개(직원용·담당자용)만 허용하고, 그 밖의 파라미터·값은 거부해야 한다.

**판단**

- **FR-004**: 버튼은 (a) 항상 허용 화면이거나, (b) 모바일 메뉴 권한이 있으면 보이고 열려야 한다. PC 메뉴 권한만으로는 버튼을 열지 않는다(D1, 2026-11-18).
- **FR-004a (필수, D10)**: FR-004의 (a)~(b)에 해당하지 않는 버튼은 보이는 모든 위치에서 빠지고, 주소로 직접 열려는 시도도 막혀야 한다.
- **FR-005**: 결재 양식 버튼은 신청 종류가 같은 PC 메뉴 행이 있을 때만 PC 권한으로 인정해야 한다.
- **FR-006**: 대응표에 짝이 없는 버튼은 모바일 메뉴 권한만으로 판단해야 한다.
- **FR-007**: PC·모바일 조회 중 실패한 쪽은 "권한 없음"으로 보고, 성공한 쪽만으로 판단해야 한다.
- **FR-008**: 버튼을 보이는 모든 위치(답변 아래 바로가기, 입력 중 추천, 근태 알림 버튼, 메뉴 목록)와 버튼을 누를 때의 최종 확인이 같은 판단을 써야 한다.

**열기**

- **FR-009**: PC 권한으로 보인 버튼도 기존과 같은 모바일 화면 주소로 열어야 한다.
- **FR-010**: 결재 양식(사직서 등)을 여는 주소는 모바일 메뉴 정보가 있으면 그것으로, 없으면 PC 메뉴 행의 프로그램 코드·쓰기 권한 정보로 만들어야 한다. [가정: PC 행의 프로그램 코드로 연 결재 양식이 모바일 행의 것과 같은 화면을 연다 — plan 단계에서 실계정 확인]

### Key Entities

- **모바일 메뉴 권한**: 직원이 5240 모바일에서 쓸 수 있는 화면 목록(현행).
- **PC 메뉴 권한**: 직원이 5240 PC에서 쓸 수 있는 프로그램 목록. 프로그램 코드·주소·신청 종류를 가진다.
- **대응표**: 위젯 버튼별로 짝지은 PC 직원용 프로그램 코드 목록(또는 신청 종류). 짝 없음이면 비어 있다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 테스트 계정(오이사공)에서 휴가신청·경조휴가신청·근무일정조회 버튼이 보이고 열린다(현행 기능 브랜치: 3개 모두 숨김).
- **SC-002 (필수)**: PC·모바일 어느 쪽에도 권한이 없는 메뉴 버튼은 하나도 보이지 않는다(위젯 화면 4곳 + 직접 열기 시도 모두). 위젯 버튼 34개 전부와 조회 성공·실패 조합 전부를 자동 테스트로 확인한다.
- **SC-003**: 대응표의 "짝" 행 전부에 대해, PC 권한만 있는 경우 보임·PC 권한도 없는 경우 숨김이 자동 테스트로 확인된다.
- **SC-004**: PC 메뉴 조회가 실패해도 모바일 권한으로 보이던 버튼은 그대로 보인다.
- **SC-005**: 챗봇 첫 화면이 뜨는 시간이 지금보다 눈에 띄게 늘지 않는다(권한 조회는 화면 표시를 기다리게 하지 않음).

## Assumptions

- PC 메뉴 권한 조회는 직원 세션만 있으면 응답한다(5240 소스 확인). 실계정 응답 형식은 plan 단계에서 실호출로 확인한다.
- 위젯이 열린 페이지가 5240 로그인 세션을 갖고 있다(현행 모바일 권한 조회와 같은 전제).
- 메뉴 권한은 화면 정리 용도이며 보안 경계가 아니다. 대응표가 틀려도 다른 직원의 데이터가 노출되지 않는다(버튼은 본인 화면만 연다).
- 대응표의 "확인 필요" 행은 plan 단계에서 확정한다. 확정 전에는 "짝 없음"으로 둔다(D3).
- 운영 배포는 이 스펙의 범위 밖이며, 기존 모바일 필터와 함께 배포된다.
