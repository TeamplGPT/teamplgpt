# Research: HR 챗봇 표 직접 출력

## R1. 어디서 붙이나 — tool 루프 한 곳

**Decision**: `server/utils/chats/toolCalling/loop.js`(fork 전용 파일)의 `toolCallingLoop`에서 처리한다.

**Rationale**: 채팅(`stream.js`), 위젯(`embed.js`), API 채팅(`apiChatHandler.js`)이 모두 이 루프를 쓴다. 루프가 돌려주는 `completeText`를 각 호출부가 대화 기록·위젯 채팅 기록에 저장한다. 그래서 루프 안에서 최종 답변을 만들면 사용자 화면과 기록이 같아진다(FR-006).

모드별 적용:
- react 모드(`utils/chats/react/`)는 문서 검색 도구만 쓴다. HR 표와 무관하다.
- @agent(aibitat, 업스트림)는 D9에 따라 범위 밖이다.

**Alternatives considered**:
- 각 호출부(stream/embed/api)에서 따로 처리: 같은 코드를 세 번 써야 한다.
- 위젯 화면에서 tool 결과를 받아 붙이기: 대화 기록과 화면이 달라진다. 위젯에 tool 결과 원문이 노출된다.

## R2. 무엇을 붙이나 — tool 결과에서 "표 블록" 추출

**Decision**: 공유 모듈 `server/utils/hrTableBlocks.js`(신규, fork 전용)가 HR tool 결과 문자열에서 사용자에게 보일 부분만 뽑는다.

1. 대상: `skillIdOf(tc.name)`가 HR skill(`hr-*`)인 tool. pseudo tool(거절·조회 불가)은 제외한다.
2. 결과에 마크다운 표(머리줄 + 구분줄 `| --- |`)가 하나도 없으면 블록이 없다. 거절·오류·"기록이 없습니다" 안내가 여기에 해당한다(D5).
3. 남기는 줄: 표 줄, `###` 소제목, 일반 정보 줄(`> 기준 근무시간…`, `> 그 외 20일은 특이사항 없음`, `> 조회 기간: …`, `> 사용 시간에는…`, `> 연장근무가 없는 달: …`).
4. 빼는 줄:
   - 맨 앞 `## HR …` 제목(모델용 머리말)
   - 끝의 공통 응답 지침(`---` + `[응답 지침]`부터 끝까지)
   - `> [`로 시작하는 지시 줄(`[응답 형식]`, `[안내]`, `[내부 참조 …]`)
   - "답변에 포함하지 마세요"가 들어간 줄
   - `[본인 데이터]` 안내(이건 루프가 나중에 붙이는 것이라 원 결과에는 없다)
5. 앞뒤 빈 줄은 정리하고, 빈 줄이 연속되면 하나로 줄인다.

**Rationale**: handler 7종을 고치지 않는다(헌장 IV, 업스트림 발산 최소). handler 출력 형식은 이미 일정하다. 모델용 지시는 `> [` 또는 공통 지침 블록으로만 붙는다(016·017에서 정한 관례). 그래서 줄 단위 규칙으로 안정적으로 가를 수 있다.

**Alternatives considered**: handler마다 "사용자용 블록" 표시를 넣는 방식. 7개 handler와 `_shared` 렌더러를 모두 고쳐야 하고, @agent 경로(D9)에도 영향이 간다.

## R3. 모델에게 주는 지시

**Decision**: 표 블록이 있는 tool 결과를 모델에 넘길 때만 바꾼다.

- 결과 안의 `> [응답 형식] …` 줄을 지운다. "표 그대로 보여주세요"는 이제 시스템이 맡으므로 지시가 충돌한다.
- 끝에 다음 줄을 붙인다: `[표 표시] 위 표는 시스템이 답변 끝에 그대로 붙입니다. 표나 목록으로 값을 다시 쓰지 말고 질문에 맞는 요점만 1~2문장으로 쓰세요. 특정 값을 물으면 첫 문장에 그 값을 쓰세요. 수치는 표에 있는 값만 쓰세요.`
- @agent 경로의 결과는 손대지 않는다(D9). 이 처리는 루프에만 있다.

**Rationale**: FR-003·FR-010. 지시를 남겨 두면 모델이 표를 다시 쓴다.

## R4. 모델 문장 거르기 (D10)

**Decision**: 표 블록이 하나라도 모인 뒤의 텍스트 라운드는 실시간으로 내보내지 않는다.

- 공급자 `handleStream`에 **캡처용 응답 객체**를 넘긴다. 이 객체는 `write`를 모아 두고, `on`·`removeListener`·`writable`·`writableEnded`는 실제 응답에 위임한다.
- 라운드가 끝나면 다음 순서로 처리한다.
  - 그 라운드가 tool 호출로 끝났으면, 모아 둔 텍스트 외 이벤트만 실제 응답에 흘려보내고 다음 라운드로 넘어간다.
  - 텍스트로 끝났으면 `sanitizeModelText(text)`로 거른다.
    - 마크다운 표 줄(`|`로 시작)을 지운다.
    - `#` 제목 줄을 지운다.
    - 숫자가 들어간 목록 줄(`- `, `* `, `• `, `1. `로 시작)을 지운다.
    - 빈 줄을 정리한다.
  - 거른 문장 + 빈 줄 + 표 블록들을 한 번의 `textResponseChunk`(`close: true`)로 쓴다.
- 비스트리밍 경로도 같은 함수로 조립한다.

**Rationale**:
- 이미 흘려보낸 글자는 되돌릴 수 없다. 그래서 거르려면 모아 둬야 한다.
- 모델 문장은 1~2문장이라 기다림이 짧다.
- 한 번에 보내는 `textResponseChunk(close: true)`는 비스트리밍 경로가 이미 쓰는 형식이다. 위젯·채팅 화면이 이미 지원한다.

**거르기 규칙의 한계**: 숫자 없는 목록 줄("- 3월과 5월은 조회되지 않았어요")은 남는다. 수치를 다시 늘어놓은 줄만 지운다. E2E로 "모델 문장 부분에 표·목록이 남은 비율"을 잰다(SC-003).

## R5. 중복·순서

**Decision**:
- 표 블록은 tool 호출 순서대로 모은다.
- 정규화한 문자열(앞뒤 공백 제거)이 같은 블록은 처음 것만 남긴다(D6).
- 이전 대화 차례의 블록은 모으지 않는다. 루프는 한 번의 사용자 질문 안에서만 산다.

## R6. 위젯 — 한도·사용·잔여 게이지 (D11)

**Decision**: okrservice `MarkdownTable.tsx`와 `markdownTableUtils.ts`를 고친다.

- 판정:
  - 머리글에 `한도`·`사용`·`잔여`가 모두 있고 첫 머리글이 `구분`이면 **한도 게이지 모드**다.
  - 첫 머리글이 `월`이면 **월별 모드**다.
- 한도 게이지 모드: 표 대신 줄마다 카드형으로 그린다.
  - 맨 위에 라벨(첫 칸)
  - 큰 숫자로 "{잔여} 시간 남음"
  - 남은 양만큼 채운 게이지
  - 그 아래 "한도 {한도}시간 중 {사용}시간 사용"
  - 잔여가 0 이하면 게이지를 비우고 숫자를 경고색으로 한다.
  - 값이 숫자가 아니면 그 줄은 값만 보인다.
- 월별 모드:
  - `사용` 칸에만 막대를 그린다. 막대 바탕 전체가 그 줄의 한도, 채운 부분이 사용이다.
  - 한도·잔여 열 막대는 없다.
  - 막대 시작점은 모든 줄에서 같다. 값 폭을 고정한 두 칸 격자로 그린다(사용자 지적 2026-10-19 — 값 길이에 따라 막대가 밀리면 안 됨).
  - 7줄 접기를 하지 않는다.
- 위 두 모드가 아닌 표는 기존 규칙 그대로다.

**Rationale**: 미리보기 v6에서 사용자가 승인했다. 018 이후 이 머리글은 서버가 만든 그대로 오므로 판정이 안정적이다.

## R7. 017 연 단위 표 출력 변경 (D12)

**Decision**: `_shared/overtimeStatus.js` `renderYear`를 다음과 같이 바꾼다.

- 조회하지 못한 달 행은 `| 2026-03 | — | — | — |`로 둔다.
- 실패한 달이 있으면 합계 첫 칸을 `합계 (조회된 N개월)`로 쓴다. 위젯은 `^(합계)\s`를 합계 줄로 인정한다.
- 표 위 정보 줄에 `> 조회되지 않은 달은 표에 —로 표시했습니다.`를 더한다.
- 017 계약 §3을 고친다.

## R8. 테스트 방법

- **단위**
  - `hrTableBlocks`: 추출 규칙, 거르기 규칙, 중복 제거
  - `loop.test.js`: 표 블록이 생기면 최종 청크가 한 번이고 문장 + 표인지, 모델이 쓴 표·숫자 목록이 지워지는지, tool 없는 대화는 그대로 스트리밍되는지, 거절 tool은 블록이 없는지
  - okrservice `MarkdownTable`: 게이지 모드, 월별 모드
- **E2E**: 기존 HR 시나리오의 `answer_pattern`에 표 줄 정규식을 더한다(예: `\| 이번 주\(\d+/\d+ 기준\) \| 12\.0 \| 4\.0 \| 8\.0 \|`, 사유 빈 칸 `\| — \|$`). `answer_not_pattern`에는 모델 문장 부분의 숫자 목록 `(?m)^[-*•] .*\d`를 넣는다(표 블록에는 목록 줄이 없다).
- **견고성**: 대표 20종 × 3회, 표 글자 일치·빈 칸 대체·목록 잔존 비율(SC-001~003)
